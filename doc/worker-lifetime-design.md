# bsc process lifetime: design report

Scope: making bsc safe as a persistent in-process worker (many packages, one process) and bluetcl safe across `bpackage clear` + reload. ORDER is closed (131/131 batch vs per-package parity, probes in testsuite/bsc.binary/batching); this report is the LIFETIME half. All file:line citations are against the read-only worktree /home/ravi/bluespec/shake-bsc/bsc-gates at 8938e26d. Runs used the installed inst/bin/{bsc,bluetcl} (build 36e10c76, an ancestor of the tip without e7f7951a's byId map; identical lifetime behaviour, confirmed per table) on scratch copies, plus small harnesses linked read-only against the tip's dist-newstyle libraries where no shipped binary can compile twice in one process. Scratch roots: .../scratchpad/worker/verify-*/.

Inputs: the verified inventory (54 entries), five reader notes, three designs, two judgements. Winner: Design 1 (content-first) with grafts from Designs 2 and 3 and both judges; details in section 3.

## 2. The reload bug, pinned

Test: testsuite/bsc.bluetcl/reload (stale.tcl). v1 `typedef Bit#(8) S; struct { S a; } T`; v2 `typedef Bit#(16) S; struct { S a; Bit#(4) b; } T`. Script: load v1, `type full StaleT::S`/`::T`, replace StaleT.bo, `bpackage clear`, load, same queries. Observed with inst/bin/bluetcl (all verifiers, identical): second `type full StaleT::T` = `Struct StaleT::T {members {{Bit#(8) a {width 8}} {Bit#(4) b {width 4}}}} {width 20} {position {v2/StaleT.bsv 4 36}}`; `Alias StaleT::S Bit#(16) {position {v2/StaleT.bsv 3 18}}` is fresh.

Table: Pred.expandSynNameMemo (Pred.hs:334-336), keyed (getIdQual i, getIdBase i) at Pred.hs:345, filled by expandNullaryMemo (343-355) from expandSyn's nullary branch (378-382: `n == 0, null as, consCTypeEnabled, not (isUnqualId i)`), never cleared (the only writer is the M.insert at 353; no other module references it).

Mechanism, step by step:
1. First `type full StaleT::T` (v1): TypeAnalysis analyzeStructCon (TypeAnalysis.hs:313-320) -> expandSynN (227/296/317) -> TCMisc.normT (1353-1368) -> Pred.expandSyn -> nullary branch -> memo miss -> expands v1's TItype body -> canonical `Bit#(8)` -> inserted under (StaleT, S).
2. `bpackage clear` (BlueTcl.hs:684-690) resets tp_binmap/tp_hashmap/tp_symtab/tp_cpack only. The .bo reader, mkSymTab (BlueTcl.hs:654) and the symtab are all fresh after reload; the memo is not.
3. Second `type full StaleT::T`: the struct's own sort and position come from `findType symtab` (TypeAnalysis.hs:169-178) -> member b and v2 position fresh; the width comes from getBitWidth's fresh runTI over the v2 Bits instance (TypeAnalysis.hs:354-371) -> 20; member a's type goes through expandSyn -> memo HIT under (StaleT, S) -> v1's `Bit#(8)`.

Differential evidence that it is this table and nothing else:
- Same script without the query before the reload -> correct `Bit#(16) a {width 16}` (verify-binmap isolate_b.tcl; verify-TStateRecover loadonly.tcl). Same reload with a fresh name T2 added -> T2 correct, T stale, in either order (fresh-name.tcl).
- Parameterized synonym `S#(n)` (bypasses the `n == 0` guard, exercises the cons table identically) -> fresh after reload (stalep.out).
- Not the cons table: ccConKey refuses TItype leaves (CType.hs:567), and the SInterface/struct probe shows ccState's own staleness only for non-synonym payloads (StaleS).
- Not binmap/hashmap/symtab: `bpackage clear` empties them (verified by the fresh alias, field, width, positions).
- Binary attribution: `objdump -d inst/bin/bluetcl` shows `Pred_expandSynzuexp_info` as the only Pred routine calling stg_newMutVarzh/stg_atomicModifyMutVar2zh; Pred.hs and MakeSymTab.hs are byte-identical between 36e10c76 and 8938e26d.
- Companion with the same key: MakeSymTab.chkSynSeen (1302-1331) does not produce the Bit#(8) but suppresses the T0013 that a redefinition to a partial application would raise (reproduced, 1a).

Why a body hash is NOT a sound key for this memo: the value is the transitive expansion; with `typedef U S; typedef Bit#(8) U`, redefining U leaves S's body text unchanged. The sound keys are the symtab build (flush at mkSymTab' entry) or the body OBJECT (pointer key), both in section 3.

## 3. Recommended model

Design 1 (content-first) with grafts. One rule decides every table: a process-global table may live forever iff its key determines the stored BYTES of its value (not merely Eq-equivalence: Bin Id writes positions and props, BinData.hs:737-744, and Bin TyCon writes the whole sort, 1268). Three tiers: VALUE (content-keyed, never flushed), DEFINITION (keyed on the defining object, flushed for memory only), REQUEST (rebuilt per request). Ids stay monotone for the process; byId is never dropped.

### 3b. The worker boundary

- Unit: one request = one `hmain args` call (bsc.hs:215-266) with the request's cwd, argv and environment, i.e. exactly the (Cwd dir, flags ++ [src]) pair the engine passes to a subprocess today (engine/src/BscEngine/Libraries.hs:363). A one-shot compile is a worker with one request.
- Shape: a pool of `bsc --worker` processes (requests over stdin/stdout, one JSON line each: cwd, argv, env subset; reply: exit code, stdout, stderr), strictly sequential per process; -j counts processes. NOT linked into the -threaded engine: SpeedyString's miss path is a non-atomic read-modify-write over three IORefs (SpeedyString.hs:51-62, 96-99), Classic.syntax, cwd, env, dumpedFiles and progArgs are process-global, and Yices allows one live context (Yices.hs:265-271), so in-process compiles would need a global lock and give no parallelism.
- Bracket: requestBegin = admission gates (traceflags subset incl. BSC_OPTIONS; suffix mode vs frozen mode; -no-use-prelude) -> dumpedFiles reset -> allocation counter -> setCurrentDirectory -> fd redirection; run hmain under handlers that map ExitCode/ErrorCall/IOException/AllocationLimitExceeded to a reply code without exiting (bsCatch, Exceptions.hs:11-33, exits today); requestEnd = doPreExitActions on the request's errh, ptrTable and Pred-memo memory flush, stats deltas.
- beginGeneration (graft from D2): one aggregator in the bsc-typecheck component holding every exported reset (CType lm/apm/ctRnfSeen with byId and n kept; GroundCType map with n kept + ptrTable; IType tconTable/internTable map with the counter kept + vsCanonTable; IConv memos; Pred memo; dumpedFiles). Two uses: the memory flushes above, and a flush-mode worker (`bsc --worker --flush-tables`) for 3-way differential testing (flush-mode, content-key, one-shot) that detects a missed table without waiting for an edit scenario. Plus an allow-list test: every top-level unsafePerformIO/newIORef/newVar in src/comp (36 cells today) must be registered in the aggregator or in the immortal list.
- Cancellation = kill the process (never the thread). Recycle after N requests or an RSS threshold; always sound.
- Error paths: internalError exits from pure code (ErrorUtil.hs:19-45); the bracket catches ExitCode mid-request; tables are consistent after any interruption (atomic inserts; keys forced before the modify); test the sequence internal-error request then clean request.

## 4. Soundness: byte-identity with one-shot compiles

Claim: for a request R with inputs I (source bytes, the .bo bytes of its import closure, flags, cwd, environment), the worker's outputs (.bo, .ba, .v with -stable-verilog, stdout/stderr, exit code, dump files) equal a fresh process's for the same I, for every request the worker admits.

1. REQUEST tier: everything built per request is built from I alone and identically in both: Flags (decodeArgs per hmain, bsc.hs:219), ErrorHandle (232), binmap/hashmap from M.empty with every .bo read from disk (step A; step B's cache admits an entry only when the bytes re-hash equal), every SymTab from emptySymtab (MakeSymTab.hs:76-91), every TI run from initPersistentState/initRecoverState (TIMonad.hs:165-185, 204-207), every GState from initGState, dumpedFiles reset, allocation counter set, cwd and env set. The one-shot process is the worker with one request, so this tier is identical by construction.
2. VALUE tier: a process-global table can differ between the two runs only in whether a lookup HITS. Under the invariant "key determines stored bytes": a ccState hit returns a TyCon whose tidied payload is byte-equal to the request's tidied payload under the caller's own position (ccAtCaller); ap hits return the caller's own spine under an id (atCaller, 459); gct canonical nodes are keyed on content ids; tconTable returns a node whose (kind, tidied sort) equals the request's; internTable nodes are rebuilt from the same leaf identities; convTMemo/convCanonMemo values are functions of content ids. The pragma-position hole (1d) is exactly a violation of this invariant and is closed by tidying SInterface pragmas in ccTidySST. Ids and uniques are observable only as identity: cmp is EQ-shortcut then structural (CType.hs:638-652), cmpT likewise (IType.hs:546-560); groundness is `id >= 0`; nothing serializes an id (BinData type_key is deep structure, 258-268; ITKI is writer-local, 290-296; FStrings by content, 705-707); nothing orders by an id at an output site (ORDER closure). Monotone counters guarantee an id never means two values; byId is never dropped, so insAp never hits ccCanonById's internalError.
3. DEFINITION tier: the Pred memo's key contains the body object; the expansion is a pure function of the body graph (Pred.hs:356-384, no symtab); a new definition is a new object. chkSynSeen is deleted. (Fallback flush at mkSymTab' entry: entries never outlive the TypeInfo bodies they were computed from.)
4. Outputs serialize values and occurrence spines, never table state: GenBin writes the CSignature and IPackage trees (sort payloads included, BinData.hs:1268, 1348), which under 2 carry the request's own payloads.
5. Unresettable configuration (progArgs CAFs, Classic.syntax CAF, one live Yices session) is pinned by the admission gates and sequential execution; refused requests run one-shot, so identity holds by construction for what the worker compiles.
6. Rule for new code (from the Classic finding): any read of a process global from pure code must sit inside an argument-dependent unsafePerformIO block (as Pred.hs:343-353 and mkTCon do); a closed `unsafePerformIO (readIORef ..)` floats to a shared CAF at -O2 even under NOINLINE with a unit argument (Classic.hs:30-36; Core dump in verify-Classic.syntax-syntaxFrozen/ghc-real).

Unproven:
- Inventory completeness: the grep classes (unsafePerformIO, IORef/MVar, NOINLINE, StableName, progArgs, getEnv) yield 36 cells, all classified; GHC floating of other closed reads is a compile-time property checked only by the mixed-suffix tests and the allow-list test.
- Tidy totality and agreement: ccTidySort and IType.tidySort must agree on which Ids are owned entities; cons_con_regen == 0 and itcon_regen == 0 on a fresh library build and suite run is the check that no site builds a payload spelling the symtab does not.
- Forcing payload Id lists at construction may surface an error thunk earlier than today; mkTCon's try demotes the leaf to raw (correct) but the first-reported diagnostic could move; the suite run is the check.
- StableName hit rate for the Pred memo: the body object may differ per source (symtab TypeInfo vs each .bo's shared entry); bounded by the number of sources, measured in step 4.
- ORDER residue outside the .bo: Verilog without -stable-verilog, bluetcl listings; the worker-mode suite is the detector; fixes are by-name ordering at the site.
- Concurrency: tables use read-then-atomicModifyIORef' with re-lookup; SpeedyString and the solver bindings do not; the design is sequential per process.
- The ccFusable 2^31 cliff and exception refusal make raw-vs-canonical history-dependent in principle (sharing only; ~10^6 compiles away).

## 7. Open questions for Ravi (each changes the design)

1. Worker shape: a pool of `bsc --worker` processes (recommended; sequential per process) or linked into the -threaded engine? In-process requires a global compile lock and the SpeedyString/solver/cwd/env/syntax globals to be made per-thread; it gives no parallelism.
2. Byte-identity oracle: per-package one-shot `bsc` (recommended) or `bsc -u`? -u is unsound today through bo-only packages (1a); if -u must remain the oracle, step 6's -u fixes move before step 1.
3. Leaf keys: exact tidied payload in the key (recommended; a hash collision would be a wrong answer) vs the literal "hash of the normalized payload"? A hash can be the bucket index with an exact compare on equality; never the sole key.
4. Pred memo: pointer key on the body object (recommended, never wrong, no flush) vs flush at mkSymTab' entry (simpler, needs the bluetcl view resets for the stale-thunk path)? If the StableName hit rate measures poorly, the flush is the fallback.
5. Syntax mode: two worker pools by suffix now (step 5 gate) and SyntaxMode-through-Flags later (step 8), or thread it first? src/Libraries mixes 66 .bs and 62 .bsv; today's `bsc -u` is already wrong on mixed trees (1a), independent of the worker.
6. Lever scope: .bo/.ba only, or Verilog too? Verilog identity needs -stable-verilog as the engine default (ASyntaxUtil.hs:712-720).
7. Traceflag requests: refuse to one-shot (recommended now; ~67 suite compiles never exercise the worker) or move the ~12 output-changing switches into Flags before the suite runs in worker mode?
8. Prelude bootstrap (-no-use-prelude) and handwritten-tycon edits: always one-shot in a fresh process (recommended), or seed the content-keyed tables from Type.handwrittenTCons after a flush?
